# Sessions operational constraints

Canonical home: ops/lib/manifests/CONSTRAINTS.md.
Authority: PoT 1.2.3 and 1.3.8, adopted with the policy by RoR-18. This is a human-consumed contract
for acting residents and delegated workers, not a second constitution or a
claim that an installed program parses this Markdown. CONTEXT identifies its
readers. Tool behavior and numeric parameters remain in each tool's existing
specification and implementation; changing this file alone changes no daemon.
Missing or conflicting contracts stop only dependent work under PoT 2.

## C01

Filing mechanics. Create a folder only within an existing base and only when
no existing folder fits. Other unmapped room folders are legacy: read/use,
but never extend until assigned port or retirement. A Control-governed folder
is not legacy merely because it is outside the room's base list.
Each storage case identifies one owner, operation and closeout condition in
its handoff or case index. No loose-root dump or operational installation is
created there. Intake is data to review, not executable authority. Temporary
clones, probes, extraction/build trees and caches use owned var/tmp scratch.
No other var lane, persistent-state home or automatic purge is implied.
At closeout, promote acceptance/recovery/record material before removing only
verified rebuildable residue. Existing content is not swept as a side effect.
Existing storage-state consumers remain unchanged only under their bounded
map entries: consumer, owner, path, ending event and assigned migration.
The map carries that current inventory, not the constitution. Private payload
remains ignored; a visible Git skeleton confers no payload admission.

## C02

Records and RoR. A kept record explains what it is, why it exists and where
to look next, for a reader without the prior conversation. Event-time next
steps are labeled as such and point to the current handoff. The act's receipt
holds its go; anomalies are counted there and enter RoR only when they alter
planned process. A ledger entry identifies decision, given time/source,
reason, act-record pointer, operator-word digest and entering writer/time.
The private companion holds words in place; the published derivative holds
the digest defined by the redact specification. Keep the private source and
the derivative preimage in verified custody before rendering. Preserve older
entries in their private source; use the accepted redact tool and its header,
never hand-edit a published historical record to conceal an earlier event.
Corrections are attributed additions, or new archive leaves citing the old.
This is no authority to render before the tool's actual acceptance.

## C03

Work in flight and standing writers. Each room resident maintains one mapped
handoff throughout work. It writes only its own handoff/team file. The role
running a tool owns that run's output, including only its appends to a shared
append ledger; the writer of an act owns its receipt. A Control claim extends
only to its exact listed paths. Another handoff is information, not authority.
At closeout, promote durable results to the existing receipt or own handoff;
a sole-copy kept result is not disposable because it was working payload.

## C04

Identity and labels. The registry supplies the exact role and plain person
name. Canon uses the role; a person appears beside that role, not instead of
it. Historical records retain the holder at the event. Chat/tab/handoff names
remain personal; a temporary role does not replace lineage. Labels use the
registered plain name. A spare is labeled as a spare; donor labels follow
C09. A resident addressed as another corrects the address before acting.
Native session selection uses verified identity, not a most-recent guess.

## C05

Reporting. Records use plain ASCII; non-ASCII in a quotation is transliterated
and noted without silently changing its attribution. Record write time comes
from a clock read during that write; events retain their own time and source.
Attribute words to their real author. Verbatim applies only to that author's
words. Re-derive an unsupported relayed conclusion before relying on it.
The failure report gives concrete observed state and a direct recovery action.
A document distinguishes implemented, installed, accepted, planned, missing
and unknown; absent material is a named-owner placeholder, not fictional
behavior. Source/freshness and measured/inferred/estimated/unknown labels
follow PoT 4.4.4; this contract adds no measurement formula.

## C06

Resident wake. Use the context read-in and the resident's own verified identity. Report
identity, fullness with its source/age or explicit unknown, and what continuity
is carried. Wait for assignment unless the opening request already gives one.
An orientation report does not appoint a role or certify native continuity.

## C07

Validation. A source or secondary fallback must be named by the specification;
label a permitted fallback as that source, never silently substitute it.
A test is synthetic; a check is read-only live or staged-layout
inspection; native live validation is a separately named operation. Reproduce
the permissions, environment, path layout and provider version the claim
depends on. Cover each setting the specification declares, not one convenient
setting. Static-valid does not imply native-load-valid. Native-load-valid
requires load and a first clean native append; successor acceptance also
requires first-person identity readback and the operator's recognition.
Do not read real body, mind or record content in synthetic tests. A reported
counter or gate must come from its actual execution, not a prepared slot.
A mutation run can switch off any guard, so no test stands one guard from a
real target: in a test a real target reaches only a pure refusal function, a
second check by a different mechanism stands at the act, and mutants run behind
a barrier they cannot reach. The barrier is a private namespace in which the
real programs are replaced by a tripwire and the real stores, logs and sockets
are masked, with the network closed and no capability left to lift a mask, each
proved before use. A root derived from the tool's own path in a clone serves
only where a trace shows the tool and its tests name no home, absolute path,
socket or program outside that root. The report states the barrier and the
tripwire count, or the trace. A packet that asks for a mutation run names its
barrier.

## C08

Mind references. A leaf permits registry keys, tool-issued entry identifiers,
citations to sources and their sections/commits, and binding digests. A source
citation is never a native session/container path. No native identifiers,
live state or secrets enter the mind. Entry screening, preview binding,
immutable leaf/pointer mechanics and chain checks use the existing mind
specification. Operator yes is per entry; the resident proposes, not ratifies.
Incident material is a reusable safeguard with its applicable boundary, not
standing blame, distrust, orientation or resident identity. Apply Control's
incident-closure rule before showing each proposed entry to the operator.

## C09

Donors, labels and recovery. A donor custody copy preserves exact bytes and
is not a rewordable narrative record. Selection freezes the donor evidence;
never use a labeling operation that appends or writes its session file.
Use only a supported label operation proven to leave that file unchanged;
otherwise retain the existing label and distinguish it by registry/move-out.
After verified custody, the live donor stays unchanged and moves out only
on named go. Before successor acceptance, rollback retains a present donor
only if byte-identical to custody; restores an absent donor only on operator
go; and stops for the operator in any other state. Replacement uses the
rotation specification's closed-writer, unchanged-preimage and atomic-swap
checks, or its operator fallback. This contract grants no body operation.

## C10

Execution preparation. Refresh canon and validate depended-on receipts before
execution; resolve provisional values before their dependent steps. A failed
generated structure is repaired before use. Stop only work that relies on a
failed gate or drift; unrelated drift, dated state lag and documented pending
conformance are reported, not converted into room-wide paralysis. Test-first
failures and the defect assigned for repair are not extra stop conditions.
Routing with a missed delivery deadline or a claimed delivery lacking the
recipient's first-person readback is a failure; awaiting the operator's relay is
pending, not failed. Opening a plan file is not execution or delivery.

## C11

Blocks. The operator opens a block. The Session Continuity Manager coordinates
within Control's working-round practice. Its existing team record names exact
writers, sources, stop condition and end time, including standing surfaces.
The operator delivers each assignment; an undelivered one assigns nothing. Members
post only their own results by the deadline and write elsewhere only within
an exact claim. A missing return is reported, not assumed. Review/audit compare
the result with the assignment. Close into the existing receipt or own handoff;
no second routing queue or compulsory ceremony is created.

## C12

Forms. New room tools use one-word names, the mapped generator, a canonical
specification and tests, and a row in the applicable registry. Specifications
use their template and cite governing policy/contracts rather than restate
them. Recurring records use the accepted template/tool form. While its form
does not yet exist, a manual record is allowed and the missing form is a
reported conformance gap. Template edits affect future records only; do not
regenerate historical records. No generated structure, packet or card grants
authority or proves the supplied slot values.

## C13

Continuity joins. Routine gauge runs append as its specification defines;
separately assigned read-only checks may use no-ledger mode and preserve the
reading's provenance. Other stages record measurements as their own spec
defines. Closeout uses the resident's own measured state and canonical card,
not remembered fullness. Minds follow C08. Rotation follows its accepted
provider-specific specification and Control's capsule/native-container/active-
window requirements; a lesser reseed is not silently equivalent. Compaction
is the operator's alternate choice, recorded before it in the resident's closing
handoff and in RoR only when it alters the planned process. Receipts use the
current form and measured protected/irreversible-act counts. No threshold,
reserve formula, hook, rotation runner or native adapter is installed here.

## C14

Workers. Use the mapped worker-disposal procedure. Its guard reads the resident
registry and all promotion records and refuses uncertain identity. A resident
with worker-origin metadata is never classified as disposable from that marker
alone. The parent remains accountable; an operator-approved registry admission
is the only promotion to resident. No new purge or archive action is authorized.

## C15

Conformance. An accepted amendment is implemented by owned small changes,
repointing maintained citations and dependent readers rather than rewriting
history. Control pointers use Control's writer route. Missing required assets
are named-owner placeholders; no reader treats them as installed or accepted.
Historical citations retain their event-time meaning. Current citations to a
retired clause are repointed using the accepted preservation map. An amendment
does not silently waive an unrelated obligation or gate unaffected work.

## C16

The Integrator (registry key `jo-hamming`, provider copilot, a clone of the
Central Repository office seated in this room) performs the repository
mechanics of other writers' reviewed work and nothing else: the exact-head
merge of a pull request the Auditor passed, on the writer's handoff of that
merge, by rebase with the passed head matched; the fast-forward of `main`; the
proof that `main` equals the passed head; the deletion of the merged branch;
and, on the writer's word, the removal of the writer's worktree.
The Integrator reviews, passes and audits nothing, writes no source, document
or record but its own handoff, and opens no pull request. It acts only on the
operator's paste. A writer who merges its own passed head remains free to do so
under Control's Git work-session standard; the Integrator is the writer's
instrument, not a second queue. The bound binds from the seating of the row;
the mechanics take effect when the office's line in Control's policy for that
office is adopted; until then the Integrator holds and merges nothing.
