# Binary Registry

Authoritative registry for `Sessions/ops/bin/*` entry points. Framework: STELA (`Projects/STELA/docs/ops/registry/binaries.md`). The two binaries, `help` and `template`, were copied from STELA on 2026-10-30 and adapted for Sessions the same day by their own writer; this registry records them and does not define their behavior. `open` was written for this room on 2026-11-12, after STELA's binary of the same name. Updated 2026-10-30 16:25 EDT.

| ID | Name | File Path | Infra Importance | Status | Notes |

| OPS-BIN-01 | Help | ops/bin/help | supporting | adapted 2026-10-30; self-test 14 of 14 | Spec: `docs/ops/specs/binaries/help.md`. Read-only wayfinding for the room: the read-in order (checked), the loop, every tool with the status its own spec declares, and specs-first search. Modes: none (menu), `read`, `specs`, `doctrine`, `term <text>`, `curriculum` (still a placeholder; no complete wake/closeout curriculum or rotate tool), `--test`. The storage entry distinguishes the versioned skeleton from ignored payload. Wired to no hook and no timer. |
| OPS-BIN-02 | Template | ops/bin/template | supporting | adapted 2026-10-30; renders from `ops/src/**/*.tpl`; self-test covers current templates and preserve-spec route | Spec: `docs/ops/specs/binaries/template.md`. Renders the room's forms from 11 templates in `ops/src/` (front matter `template_type`, `template_id`, `template_version`, `requires_slots`; `{{SLOT}}` markers). Tool-set mode writes the script, spec and test, refusing existing targets unless `--preserve-spec` explicitly keeps an existing regular spec byte for byte while creating only the missing script and test. It prints a registry row without writing the registry. Report mode, including `source-change`, requires every slot and can print or use `--out PATH`. Refuses unknown/duplicate/empty slots, unrendered markers and overwrites. Flags: `--slot KEY=VALUE`, `--slots-file PATH`, `--out PATH`, `--dry-run`, `--root=DIR`, `--preserve-spec`, `--test`. |
| OPS-BIN-03 | Open | ops/bin/open | critical | built 2026-11-12 on the operator's direction; shows and records; no tool requires it yet | Spec: `docs/ops/specs/binaries/open.md`. Tests: `tools/test/test_open.py` (`TEST-56`). The read-in a resident runs before it works. It finds the caller as `mind.py` does, prints the clauses that `CONTEXT.md` X04 lists for every reader and for each delivery function the open packet's leaf gives the caller, read from `main`, and prints a file of the law whole when the caller's body has not been shown it as it stands, in parts of at most 9,000 bytes. When the last part is printed it records the OPEN under `logs/open/`. A function is read from that leaf and from nowhere else; when no open packet names the caller, all four are shown. An OPEN is good for one body, one text of the law and twelve hours, and only while it has shown every function the open packet gives its holder. Modes: `--intent TEXT`, `--next`, `--check`, `--roster`. Python 3, standard library. Wired to no hook and no timer. |
