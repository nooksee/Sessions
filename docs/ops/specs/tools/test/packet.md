# Technical Specification: tools/test/test_packet.py

Test file: `Sessions/tools/test/test_packet.py`. Tool under test: `Sessions/ops/lib/scripts/packet.py`. Tool spec: `docs/ops/specs/scripts/packet.md`. Registry entry: `docs/ops/registry/test.md` (`TEST-55`). Status: 102 tests (measured 2026-11-13: 102 run at umask 0002, in about 110 seconds).

## Purpose
Prove, in synthetic rooms only, that a change reaches `main` only as one dispatch packet: that each station runs only for the key that carries its function and only on what the station before it left, that the audit binds the exact tree, that the ship station lands the packet and leaves the room clean and level with origin, and that the required check refuses every pull request that is not one valid packet.

## Invocation
- Command, from the room root: `python3 -I -B tools/test/test_packet.py`
- Required flags: none. Positional arguments: none (standard `unittest` arguments are accepted).
- Expected exit behavior: `0` when every test passes; `1` when any fails or errors.
- Reviewers also run it at umask 0002, 0022 and 0077.

## Inputs
- `ops/lib/scripts/packet.py`, imported and called in process through its `main`; with it, `mind.py` (the caller), `redact.py` (the public check) and `constitution.py` (the authorization gate), each loaded or run as the tool does.
- A template built once per run and copied for each test: a bare origin, a room cloned from it on `main`, and a program named `gh`. The room holds two pages to edit, three stand-in suites, two stand-in self-tests, a law file and a stand-in for the packet tool, so the gate's bootstrap rule sees a base that holds it.
- A registry beside the room with five invented residents whose sessions are synthetic `0000` identifiers, and one registered to another room. Every station declares its caller through `mind.py`'s test seam; the parent's own value never leaks in.
- The stand-in `gh` is first on `PATH`. It keeps its state in a file, answers the same `gh api` calls the tool makes, and merges by rewriting the branch's commits onto the bare origin's `main`, so the landed commits have new ids as a rebase merge gives them.
- A clock that advances one minute per command. No real room, registry, remote or account is read or written.

## Outputs
- Writes only inside its own temporary directories, removed after each test and after the run.
- Exit codes the tests assert on the tool: `0` done, `1` a failed gate or required check, `2` a refusal, `3` pending or held.

## Invariants and failure modes

**The leaf (11).** A leaf round trips at every station, with several paragraphs and with amendments. Twelve departures from canonical form are each refused. Each rule of a valid leaf is refused where it breaks, twenty-six cases: the function keys, the branch, the base, the limits, a heading line, a character outside plain ASCII named by its name, the scope, the gates, the amendments, the results and the audit. Results must hold passing gates that the contract names. Scope entries are plain paths and never a leaf; scope matches an exact path or a folder prefix and nothing that merely looks alike. A quotation, a host path, a session identifier and a bare short hash are each held back from a public leaf, and a hash after the word commit passes. The path of a policy snapshot or of its authority leaf passes, and a name that only resembles one does not. The draft form round trips and names what is not filled. A relayed error line never carries an address credential.

**Draft and open (12).** The draft is private and the one it replaces is kept. Open makes the one packet from clean `main`: the worktree on its branch, the contract in the leaf, a ledger line with the contract digest and the function keys at private modes, the draft consumed, the room still clean, nothing on origin. A second packet is refused. Open refuses a room on another branch, with uncommitted paths, behind origin, or holding commits origin does not; the Contractor as Auditor; a key that is unregistered or registered to another room; a malformed scope or gates; a quotation or a host path in the contract; an unverified caller; no draft; an origin that does not answer; a number whose branch already exists here or on origin, naming the branch and the remedy. The paths of a policy snapshot may be named in a scope. An open that fails after the worktree is made leaves no worktree and no branch. The tool refuses a linked worktree, or a folder that is not a checkout root, as its room.

**Work, close and audit (22).** `status` names each station and whose turn it is, shows the caller, counts and names paths outside scope, and moves no ref and no index; it says stop when the room is not clean `main`. `diff` shows the exact change the audit binds, a new file and a removed one included and the leaf left out, under the tree the leaf records. Close records the count of paths, each gate with its exit code, the deviations, the narrative and the tree, which an independent computation matches; the gate log is private. Close is refused for every caller but the Contractor, for a path outside scope (named exactly, whatever its name), when nothing changed, when a gate names nothing, and while the room's own checkout is dirty. A failing gate ends the close with exit 1, keeps the log and leaves the leaf unclosed. A close that fails after an earlier close and a PASS voids both, on the same tree, so nothing ships on them. A gate that writes outside scope is caught after the gates. Gates run at umask 0002 without the test seam. `full` runs every suite and both self-tests. The narrative is checked before any gate runs. A contract edited by hand stops every station. Amend is the Integrator's alone and voids an earlier close. Audit is the Auditor's alone, is refused before close and after any change, records PASS or FAIL on the exact tree, and a FAIL returns the packet to the Contractor, whose next close clears it. A damaged leaf stops the stations until its Integrator, and no other caller, restores it from the ledger. A verdict or a result written into the leaf by hand is refused by `status`, `audit` and `ship`, and after a restore the station is run properly. With the ledger gone nothing is restored, and the Integrator abandons with the work kept; a damaged leaf can still be abandoned by its Integrator.

**Ship (34).** A packet lands end to end: one commit of exactly the scope and the leaf, the push, the pull request with its title and body, the check, the merge by rebase, the room's `main` the same commit as origin's and clean, the worktree and both branches gone, the ledger lines in order and the landing proof posted. The next packet takes the next number, carries two functions into the form, and lands an added and a removed path. Ship is pending while the check has not started or is running, and resumes without a second commit or pull request; `--wait` polls. A red check is exit 1 and the reworked packet lands on the same pull request. The head rests 300 seconds. A reviewer whose marker says it is running holds the merge, the same marker from an account that is not an application is not believed, a marker that cannot be read is passed over, and one that has said running for over 1,800 seconds is taken as stopped. A reviewer that was asked, a person, an application or a team, holds the merge until it answers, is asked only once the head has rested, and is waited for at most 900 seconds from the opening of the pull request; an opening time that cannot be read is long ago, and is said to be unread, not counted in seconds; an answer that is no pull request where the pull request is read, an empty object, null, false and a list among them, refuses the ship with no merge call made and no traceback, and refuses the landing record's read. The request is read from the pull request's events as GitHub gives them for an application that reviews by itself: it stands in the events and never in the list of requested reviewers, and the review carries another name with the same account number. The events are read in order and across every page: a review or a withdrawn request ends the wait, a later request starts it again, another account's review does not end it, a reviewer with no number is known by name, GitHub's own list is added, and an event that names no reviewer is passed over. Events that cannot be read, by a refusal or by an answer that is no list, an empty object, null and false among them, stop no landing, and the tool and the landing say so; an empty list is read, and is empty. The landing line, the ledger and the landing proof name every account that reviewed with its count of findings, a reviewer that was asked and did not answer, one that was asked again after its review a second time, a finding that arrived after the merge as unanswered, and a reviewer still running; the pull request's own account and a passer-by's marker are not reviewers, a marker that cannot be read names no reviewer while one that reads and says nothing does, and reviews or comments that cannot be read, an empty object or null in place of the list among them, stop no landing. A reviewer is one account: with one account number under two logins, as GitHub gave it on a real pull request, it is named once, by the login on its review, or by the login it has where it left no review; with no number a login is all there is; and the pull request's own account is left out by its number too. The record counts the findings answered without a change, by the comment's present line, and says nothing of the kind for an unanswered one; such a landing lands. The reviews and the comments are read across every page, in the record and in the check for a running review. An item that is no object, or one whose user is no object, is refused plainly by each reader. In the comments or the review comments, which the station reads before the merge, it refuses the ship with no merge call made and no traceback. The reviews are read only for the landing record, after the merge, so such an item there stops nothing: the record is not read, and the landing says so. A reviewer asked again is waited for from that request and a request with no time of its own from the opening; one that is late is named while another is still waited for. An answer that is no list where the review comments or the comments should be one, an empty object, null and false among them, refuses the ship with no merge call made. An unanswered inline review finding stops the merge and is named with its address, a reply from another account does not answer it, the pull request's own account's reply does, and findings are read across every page. `--hold` stops before the merge with no merge call made. Ship is the Orchestrator's, or a recorded fallback's, whose reason must be one publishable line from a registered resident. Ship refuses when origin's `main` moved, when the content is not what the Auditor passed, and when the room's checkout is dirty. It finishes a merge made outside the tool, and stops when the worktree changed after that merge. It never forces a push, and a push switches push negotiation off for the call. A branch that cannot be removed from origin keeps the packet and its worktree until it can. The leaf ships even where an ignore rule hides it. The authorization gate runs before anything is pushed. What the host says is relayed: a refused call, an answer that is not JSON, and a missing `gh`. The owner and repository come from the origin address in four forms. No output, ledger line or leaf carries a session identifier.

**Abandon and sync (5).** The Integrator, and no other caller, abandons a packet that never reached origin; the work is kept as a private patch without the leaf, the number is free again, and the patch applies in the next worktree. Once the branch is on origin the Orchestrator abandons, which closes the pull request and removes the branch; a fallback may; a merged packet is never abandoned. Sync brings a clean room level and refuses a dirty one. A folder at the worktree's path that is not the packet worktree stops everything.

**The gate (18).** One valid packet is built once and each case derives a commit from it by plumbing. The valid packet passes, and the gate moves no ref and dirties no checkout. The gate does not apply while the base holds no packet tool, and applies from the next pull request. It does not apply either while the base holds the first tool and no leaf, and applies again once the base holds another tool or a leaf. Each of these fails with its own reason: a path outside scope; no leaf; the wrong number; content changed after the audit; the Contractor as Auditor; an earlier leaf edited or removed; two leaves; a branch that is not a packet branch, or another date than the leaf names; a leaf out of canonical form; a recorded gate that failed; no audit; a FAIL verdict; deviations that are not a count; a quotation or a host path in the leaf; a base that moved; a leaf that names another base. A pull request that changes the gate itself is named. The leaf chain passes when numbered without a gap and fails on a gap or on a leaf that opens with another id. The command refuses when its arguments are missing or its head is no commit.
