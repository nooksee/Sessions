## First Principles Rationale

A record is never reworded (PoT 1.2.13), and some records must leave the room: the ledger, the receipts, the handoffs that a public repository or a reader outside the house will see. What must not leave is of three kinds, and the room already names each: the operator's exact words, which are his and are quoted in the ledger by law (1.2.10); the host's paths, which describe one machine; and session identifiers, which name bodies (5.1, 5.4). `redact` renders a public copy in which exactly those three are replaced and nothing else moves, so that the public copy can be checked against the private record by anyone who holds both, and the private record stays the authority.

Two choices follow from the room's experience. First, a digest, not a blank: the operator's words are replaced by their sha256, so the public ledger still proves which words were said, and the private words file lets a holder verify them. Second, fail closed: the tool classifies by rules, and anything the rules cannot place stops the render and is reported for a decision; it never guesses. PR #5 and PR #7 of 2026-11-01 taught the third rule: a session identifier survives as a truncated prefix as easily as whole, so the rules match truncated forms too.

## Mechanics and Sequencing

1. **Commands.** `redact check RECORD [--decide ID=words|keep|session ...]` reports every span the rules would change and every span they cannot classify, and writes nothing. `redact render RECORD --out PATH [--words-out PATH] [--decide ...]` writes the public copy and, if asked, the private words file. Options are repeatable `--decide` values only; everything else is positional or required.
2. **Input.** The record must be a regular file, not a link; it is read as bytes and decoded as strict UTF-8; a file that is not UTF-8 is refused before anything is classified. A body is refused by its resolved name, `.jsonl` in any letter case: a body is not a record, and this tool never reads one. A file that begins with the tool's own header line is a public copy and is refused as input.
3. **Spans, found line by line, in this order, each claiming its characters once.**
   - **Quotes.** Double-quoted stretches outside code include straight, curly,
     low and angle double quote marks; single quotes are not quote markers.
     Code is an inline backtick span or a fenced block. A fence remembers its
     opening character and length (at least three); only the same character,
     at least that length, with whitespace-only remainder closes it. Literal
     opposite or shorter fences and marker lines with trailing information
     do not close the block. Existing same-line backtick spans stay inline;
     tilde info strings may contain literal tilde markers without changing
     which later line closes the block.
     Paths and identifiers are still inspected inside code, but quotes are not.
     A first bold label containing words or direction identifies a words
     field. Accept its entire first-to-last quoted stretch only with an even
     marker count and no unquoted payload before or after the outer markers.
     Otherwise classify the entire field payload as unknown and refuse the
     render. An explicit words decision can digest that whole malformed
     payload; keep or session decisions for it are refused. Never digest
     only an inner fragment and leave a private tail public.
     Elsewhere, quote markers pair in order: attribution within the preceding
     80 characters classifies words; unattributed or unbalanced quotes remain
     unknown. A quote within inline backticks is code, not a quote.
   - **Workflow ids.** `wf_` followed by 8 and then 3 hexadecimal characters is the Workflow tool's run id and stays; nothing longer after `wf_` is one.
   - **Host paths.** An absolute path beginning `[host path 1]`, `[host path 2]`, `[host path 3]`, `[host path 4]`, `[host path 5]`, `[host path 6]`, `[host path 7]`, `[host path 8]`, `[host path 9]` or `[host path 10]`, or a path beginning `[host path 11]` or `[host path 12]`, wherever it starts (after `file://`, a doubled slash, a bracket or a colon alike), up to the next whitespace, quote mark, backtick, pipe, closing square bracket, comma or semicolon; parentheses inside it are kept while balanced; it continues past a space when the next segment still carries a slash (`[host path 13]`); a trailing `.`, `,`, `:` or `;` is left to the sentence. Class `path`. A host path in Claude's project-slug form (`[host path 14]...`, `[host path 15]...`, also after `projects/`) is a host path too. System paths such as `/usr/bin/python3`, `/etc/...`, `/proc/...` and room-relative paths such as `Sessions/PoT.md` are not host paths and stay; a Windows path is out of scope and is named in the warnings.
   - **Session identifiers, whole.** The 8-4-4-4-12 hexadecimal shape. Only a hexadecimal neighbour blocks a match, so `agent-<id>.jsonl`, `session_<id>`, `<id>_old` and `wf_<id>` are found. Class `session`. One inside a URL (after `http://` or `https://` with no space between) is unclassified, since a link may carry an identifier that is not a session.
   - **Session identifiers, truncated.** The whole hyphenated hexadecimal token that begins with an 8-hex head (a trailing hyphen included), holding at least one letter and one digit anywhere in it, so `20261101-0654` is a number and `[session prefix 1]` is an identifier. The token is taken whole or not at all: one that a keep context precedes is a digest and stays (`commit abcdef12-0000` and `commit abcdef12-dirty`); one joined to a word (`[session prefix 2]_x`) is unclassified, whole, for a decision; any other is class `prefix`. Nothing of the token is ever left beside its placeholder.
   - **Bare hex runs** of 8 or more characters with at least one letter and one digit (so a date such as `20261101` is never one). A run whose preceding characters end in the whole word `session`, `body`, `bodies`, `donor`, `container`, `thread`, `successor`, `rotation`, `spare` or `uuid`, with an optional `:`, `=`, `_` or `-` between, is class `prefix` (`id` alone is no context: a commit id or a build id is not a session). Otherwise, a run that begins any session identifier found anywhere in the record, whole or truncated, is unclassified whatever stands before it: a kept run beside its own placeholder would hand a reader the mapping. Otherwise a run of 40 or 64 characters is a Git object hash or a sha256 and stays, as does a run whose 24 preceding characters end in the whole word `sha256`, `sha`, `hash`, `digest`, `commit`, `head`, `merge`, `blob`, `tree`, `object` or `PR` (so `overhead` keeps nothing, and a heading marker `##` or a `#` is no context). A run that begins a Git hash or sha256 written whole elsewhere in the same record is the head of that digest and stays. Any other run is unclassified. Every run the rules keep is reported as kept, with its reason, so that the check output is a complete account.
4. **Decisions.** A quote is decided before the identifier rules run over its line, so a quote that is kept, or still undecided, has the paths and identifiers inside it found and placeholdered as anywhere else; only a `words` span is digested whole. After every line is classified, a second pass holds the whole record to one rule: no kept run may equal or head an identifier the record placeholders, whatever placed that identifier (its shape, a context word or a decision); such a run becomes unclassified, and a `keep` decision that would keep one is refused, since the copy would otherwise carry the identifier beside its own placeholder. Every span has an id, the first 12 hexadecimal characters of the sha256 of its kind and its exact text; `check` prints the id of every unclassified span. `--decide ID=words`, `ID=keep` or `ID=session` classifies that span and no other: `words` and `keep` for a quote, `session` (a truncated identifier) and `keep` for a hex run. A decision for a span the rules classified themselves, for a span not in the record, or with a value the kind does not take, is refused: the tool offers no override of its own classification, so that a decision can never silently keep an operator's words. Decisions live on the command line of the run and are counted in the header of the public copy; the run's command line is the record of them.
5. **Numbering.** Whole identifiers are numbered by first appearance; a truncated identifier takes the number of the whole identifier it begins, if one is in the record, and otherwise the number of its 8-hex head, so two truncated forms of one body are one placeholder. Host paths are numbered by first appearance of the exact text. The same identifier or path is therefore the same placeholder throughout the copy.
6. **Rendering.** Class `words` becomes `[words sha256=<64 hex>]`, the digest of the exact UTF-8 text between the quote marks, the quote marks kept; `path` becomes `[host path N]`; `session` becomes `[session N]`; `prefix` becomes `[session prefix N]`; `keep` is left as it is. A host path or identifier inside a `words` span is digested with the words and never placeholdered. Every character outside a replaced span is written as it was read: line endings, tabs, non-ASCII, a missing final newline. The public copy begins with one added line, an HTML comment naming the source by its sha256 only (never by its file name, which may itself carry an identifier or a path), the rules version, the counts and the number of decisions, so that a reader can tell a copy from a record and re-render to verify it.
7. **Outputs.** `--out` and `--words-out` are created exclusively, mode 0644 and 0600: a temporary file in the same directory, then a hard link to the final name, which fails if the name exists; the temporary file is always removed. An existing file at either name, or a parent that is not a directory, is refused before any write; both temporary files are written before either is linked, and a failure removes everything this run created, so a two-output render writes both or neither. The words file holds a header and one line per digested span, `sha256=<64> | line N | <the words>`, in record order; it is private by construction and never enters Git.
8. **Exit codes.** 0: check found nothing unclassified, or render wrote. 1: something is unclassified; check lists it and render writes nothing. 2: a refusal or a usage error (input missing or not UTF-8, a body as input, an existing output, a write failure such as a missing directory, a bad or stale decision). `check` prints a report line per span and a summary line; `render` prints the same and the paths written. The report never prints words, and prints a path or a hex run by its first eight characters only, since either may carry an identifier.

## Integrity Filter Warnings

- **The private record stays the authority.** The public copy is a derived document; the tool never edits, moves or rewords the record it reads (1.2.13), and never writes over any file.
- **Fail closed, no overrides.** An unclassified span stops a render. A decision applies only to a span the rules could not place; the rules' own classifications cannot be overridden by a decision, by design. A rule that is wrong is changed in this file and the tool, with its tests, and the rules version in the header changes with it.
- **Scope, stated plainly.** The rules know three things: quoted operator words, host paths and session identifiers. They do not detect personal names, user names on their own, medical content, secrets, Codex thread identifiers in any shape but the UUID one, Windows paths, single-quoted words, a host path written without its leading slash, or a path inside a URL after its host name. The body refusal is by name: a hard link named `.md` to a body would be read as a record, and nothing but the reader's care prevents that. `container` is a session context by design, so a Docker container id after that word is placeholdered too; over-placeholdering is the safe direction. A host path in underscore italics is found; its closing underscores stay outside the placeholder. Attribution is conservative: any double-quoted text within 80 characters after `Kevin` or `operator` on the line is digested as his words, file names included; a reader who wants such a quote kept has no override and must restate the line in the record's correction, by design. A record that carries any of those needs a reader before it leaves the room; this tool is one gate, not the last.
- **The words file is private.** [words sha256=520ff56f2937d458826d264ef8d565e36f9a100c3f731957dda78a2dc5232227]
- **Check before render, and keep the command line.** The decisions a render took are counted in the public copy's header, not listed; the command line that ran it is the record of which spans were decided and how, and belongs in the receipt of the split.
- **Bodies are never input.** A `.jsonl` file is refused by name; message content is never read or printed; the report prints a quote's length and a hex run's first eight characters, never the words.
